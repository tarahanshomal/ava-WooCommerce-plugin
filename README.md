# پیامک آوا برای ووکامرس

افزونهٔ مستقل **ava-sms-for-woocommerce** برای ارسال پیامک‌های سفارش ووکامرس از طریق سرویس آوا، توسعه‌یافته توسط [طراحان شمال](https://github.com/tarahanshomal).

- پیامک وضعیت سفارش برای مشتری، با متن جداگانه و قابل ویرایش برای هر وضعیت.
- اطلاع‌رسانی سفارش جدید و وضعیت‌های منتخب به شماره‌های مدیر فروشگاه.
- ارسال دستی از صفحهٔ سفارش و ارسال آزمایشی با تأیید مدیر.
- صف ارسال در پس‌زمینه، جلوگیری از ثبت تکراری اعلان خودکار و گزارش وضعیت پیامک.
- تنظیمات فارسی، پشتیبانی از شماره‌های ایرانی و ارقام فارسی/عربی.
- استفاده از API سفارش ووکامرس برای سازگاری با HPOS و پشتیبانی از تسویه‌حساب کلاسیک و بلوکی.

## نصب

1. برای ارتقای نسخه‌های قبلیِ دانلودشده از آوا، فایل **ava-WooCommerce-plugin-1.2.3.zip** را از صفحهٔ دانلود آوا یا انتشارها بگیرید. این بسته همان پوشهٔ قبلی را جایگزین می‌کند. برای نصب تازه یا ارتقای نصب دارای پوشهٔ `ava-sms-for-woocommerce`، فایل **ava-sms-for-woocommerce-1.2.3.zip** را بگیرید؛ پس از پذیرش در WordPress.org نصب از فهرست افزونه‌ها نیز در دسترس خواهد بود.
2. در وردپرس به **افزونه‌ها ← افزودن افزونه ← بارگذاری افزونه** بروید و ZIP را نصب و فعال کنید.
3. در **ووکامرس ← پیامک آوا** تنظیمات اتصال و متن پیام‌ها را وارد کنید.

هنگام ارتقا، گزینهٔ «جایگزینی نسخهٔ فعلی» وردپرس را انتخاب کنید. دو بسته را هم‌زمان نصب نکنید؛ پوشهٔ بسته باید با افزونهٔ فعلی یکسان باشد تا تنظیمات و گزارش‌ها در همان نصب حفظ شوند.

نیازمندی‌ها: PHP 7.4 یا جدیدتر، وردپرس 6.5 یا جدیدتر، ووکامرس 8.2 یا جدیدتر و دسترسی HTTPS از فروشگاه به پنل آوا.

## راه‌اندازی اتصال

در پنل آوا یک کلید API با دسترسی‌های **`sms:send`** و **`sms:read`** بسازید. نشانی پیش‌فرض پنل **`https://ava.tarpardaz.com`** است؛ برای پنل اختصاصی، نشانی HTTPS همان پنل را وارد کنید. شمارهٔ فرستنده را فقط اگر برای حسابتان فعال است تنظیم کنید؛ خالی گذاشتن آن، انتخاب فرستنده را به آوا می‌سپارد.

شماره‌های مدیر را وارد کنید، وضعیت‌های مورد نظر و متن پیام‌ها را انتخاب کنید و ارسال خودکار را فعال کنید. ارسال خودکار پس از نصب غیرفعال است. برای بررسی دریافت پیامک از فرم ارسال آزمایشی استفاده کنید؛ این فرم پیامک واقعی و هزینه‌دار ارسال می‌کند و تأیید آن الزامی است.

در بالای صفحهٔ تنظیمات، **ماندهٔ قابل مصرف حساب آوا** همراه موجودی کل و اعتبار رزروشده به **ریال** نمایش داده می‌شود. این مقادیر از کیف پول واقعی آوا با درخواست فقط‌خواندنی `GET /api/v1/wallet` و کلید فعلی دریافت می‌شوند؛ روشن‌بودن ارسال خودکار لازم نیست. کلید دارای مجوز `sms:send` یا `wallet:read` می‌تواند موجودی را بخواند. مشاهدهٔ موجودی تأیید تحویل پیامک نیست.

موجودی تا ۶۰ ثانیه برای همان نشانی پنل و کلید ذخیره می‌شود؛ «تازه‌سازی موجودی» مقدار جدید را دریافت می‌کند و «شارژ حساب آوا» کیف پول همان پنل را باز می‌کند. خواندن و تازه‌سازی موجودی پیامک نمی‌فرستد و هزینهٔ پیامکی ندارد. اگر اتصال، مجوز یا پاسخ معتبر نباشد، خطای واضح نمایش داده می‌شود؛ موجودی صفر یا ماندهٔ قدیمی به‌عنوان نتیجهٔ تازه نمایش داده نمی‌شود.

کلید ذخیره‌شده در فرم بازنمایی نمی‌شود. برای حفظ کلید قبلی، فیلد کلید را خالی بگذارید؛ برای تعویض، کلید جدید را وارد کنید. کلید را در مخزن Git، گزارش خطا یا تصویر تنظیمات منتشر نکنید. در صورت تمایل، به‌جای ذخیرهٔ کلید از طریق فرم، آن را در `wp-config.php` و پیش از خط پایان تنظیمات تعریف کنید:

```php
define( 'AVA_WOO_API_KEY', 'YOUR_AVA_API_KEY' );
```

مقدار نمونه را با کلید واقعی خود جایگزین کنید. وقتی این ثابت تعریف شده باشد، فیلد کلید در افزونه غیرفعال می‌شود و مقدار ثابت در تنظیمات پایگاه داده کپی نمی‌شود.

اعلان «سفارش تازه» برای سفارش‌های ثبت‌شده از تسویه‌حساب کلاسیک یا بلوکی ارسال می‌شود. سفارش‌های ساخته‌شده در مدیریت یا REST API، در صورت انتخاب وضعیت مربوط، اعلان تغییر وضعیت دریافت می‌کنند. قالب مدیر برای اعلان سفارش تازه و وضعیت‌های منتخب مدیر مشترک است؛ متن آن را با توجه به این کاربرد تنظیم کنید.

## متغیرهای متن پیام

| متغیر | مقدار |
| --- | --- |
| `{order_id}` | شناسهٔ داخلی سفارش |
| `{order_number}` | شمارهٔ نمایشی سفارش |
| `{order_status}` | عنوان وضعیت سفارش |
| `{order_total}` | مبلغ سفارش به صورت متن |
| `{currency}` | ارز سفارش |
| `{billing_first_name}` | نام مشتری |
| `{billing_last_name}` | نام خانوادگی مشتری |
| `{billing_phone}` | شمارهٔ ثبت‌شدهٔ مشتری |
| `{payment_method}` | عنوان روش پرداخت |
| `{shipping_method}` | عنوان روش ارسال |
| `{site_name}` | نام فروشگاه |

نمونه:

```text
{billing_first_name} عزیز، سفارش {order_number} شما در {site_name} به وضعیت «{order_status}» تغییر کرد.
مبلغ سفارش: {order_total} {currency}
```

متن نهایی پیام باید بین ۱ تا ۱۰۰۰ نویسه باشد. متن‌های بلند ممکن است به چند بخش پیامک تقسیم شوند؛ هزینه و پذیرش نهایی را آوا تعیین می‌کند. افزونه اعلان‌ها را با پیامک متنی ارسال می‌کند. API الگوی OTP آوا مخصوص رمز یک‌بارمصرف است و برای پیام وضعیت سفارش استفاده نمی‌شود.

## بررسی اتصال بدون ارسال پیامک

نسخهٔ **۱٫۲٫۳** دکمهٔ «بررسی اتصال بدون ارسال پیامک» را به تنظیمات اضافه می‌کند. پس از ذخیرهٔ نشانی و کلید، این دکمه با درخواست فقط‌خواندنی `GET /api/v1/connection` اعتبار کلید، مجوزهای `sms:send` و `sms:read` و آمادگی حساب و سرویس پیامکی را بررسی می‌کند. این بررسی پیامک یا هزینه ایجاد نمی‌کند و موجودی، بررسی محتوا، مجازبودن خط و گیرنده و تحویل هر پیام همچنان در مسیر همان ارسال بررسی می‌شوند. پنل‌های قدیمی که مسیر بررسی اتصال را ندارند، نیاز به به‌روزرسانی را نشان می‌دهند.

پس از بازیابی رمز یا تغییر امنیتی حساب آوا، کلید قبلی ممکن است باطل شود. افزونه علت‌های شناخته‌شدهٔ لغو، انقضا و تغییر امنیتی را با راهنمای ساخت و ذخیرهٔ کلید تازه نمایش می‌دهد. خلاصهٔ بررسی حداکثر یک روز و فقط برای همان نشانی و کلید ذخیره می‌شود؛ کلید و پاسخ خام سرویس نمایش داده نمی‌شوند. تعویض کلید، پیامک‌های قبلی ناموفق یا نامشخص را خودکار دوباره ارسال نمی‌کند.

## تأیید یک‌بارهٔ قالب سفارشی

نسخهٔ **۱٫۲٫۰** علاوه بر متن نهایی پیام، قالب اصلی، شناسهٔ مستقل فروشگاه و نسخهٔ قالب و فقط متغیرهای استفاده‌شده را همراه همان درخواست ارسال می‌کند. پس از اولین تأیید قالب سفارشی در پنل آوا، پیام‌های بعدیِ همان فروشگاه و همان نسخه به تأیید جداگانه نیاز ندارند؛ تغییر نام مشتری، شماره سفارش یا مبلغ، نسخهٔ قالب را عوض نمی‌کند. با ذخیرهٔ متن ویرایش‌شده، نسخهٔ تازه ایجاد و تأیید دوباره لازم می‌شود؛ حتی بازگرداندن متن به نسخهٔ قبلی پس از ذخیرهٔ یک ویرایش، نسخهٔ تازه است.

تأیید قالب بین فروشگاه‌ها مشترک نیست. تغییر عنوان فروشگاهِ استفاده‌شده در متن نیز نسخهٔ تازه می‌سازد. شناسهٔ فروشگاه کپی‌شده هنگام تغییر نشانی اصلی وردپرس جدا می‌شود. متن و مشخصات قالب هم‌زمان با پیام در صف ذخیره می‌شوند؛ تغییر سفارش یا تنظیمات، پیام‌های قبلیِ صف را بازنویسی نمی‌کند.

این قابلیت به نصب همین نسخه و پشتیبانی پنل آوا نیاز دارد. نسخه‌های قدیمی فقط متن نهایی را می‌فرستند و تأییدشان به قالب متغیر تعمیم داده نمی‌شود. قالب‌ها یا مقادیر خارج از محدودهٔ پشتیبانی، مسیر عادی بررسی محتوا را دارند. داده‌های قالب، مانند متن پیام، باید در سیاست حریم خصوصی فروشگاه لحاظ شوند. بستهٔ جاری از [صفحهٔ رسمی دانلود آوا](https://ava.tarpardaz.com/plugins) در دسترس قرار می‌گیرد.

## صف و گزارش ارسال

ارسال از فرایند تسویه‌حساب جداست و در پس‌زمینه انجام می‌شود. صف از Action Scheduler ووکامرس و در نبود آن از WP-Cron استفاده می‌کند. در فروشگاه‌های کم‌ترافیک، اجرای منظم cron وردپرس را در هاست تنظیم کنید.

**ثبت در صف، پذیرش توسط سرویس و تحویل به گوشی سه وضعیت متفاوت‌اند.** پاسخ ۲۰۲ آوا فقط ثبت درخواست در صف را تأیید می‌کند. در گزارش‌ها، وضعیت ثبت‌شدهٔ آوا را بررسی و در صورت نیاز گزارش را به‌روزرسانی کنید. اگر ارتباط هنگام ارسال قطع شود و نتیجه مشخص نباشد، افزونه پیام را خودکار دوباره ارسال نمی‌کند تا احتمال پیامک و هزینهٔ تکراری کاهش یابد.

انتظار تأیید محتوا، کمبود اعتبار، محدودیت ظرفیت و آماده‌نبودن اتصال جدا از صف ارسال نمایش داده می‌شوند. پیگیری وضعیت فقط خواندنی است؛ پس از تأخیر با فاصلهٔ حداکثر یک ساعت تا نتیجهٔ نهایی ادامه دارد. کارهای پیگیری ازدست‌رفته در اجرای ساعتی cron بازیابی می‌شوند و پیام ثبت‌شده دوباره ارسال نمی‌شود. ارتقا، اطلاعات صف قبلی را حفظ می‌کند.

اگر پس از ثبت پیام در صف، دامنهٔ پنل، کلید API یا خط فرستنده را عوض کنید، پیام‌های قبلی صف لغو می‌شوند تا از ارسال با حساب یا خط دیگری جلوگیری شود. گزارش پیام‌های قبلی نیز فقط با اتصال همان حساب قابل دریافت است.

اعلان خودکار یک سفارش برای همان وضعیت، گیرنده و مخاطب دوباره ثبت نمی‌شود. بازگرداندن سفارش به همان وضعیت، پیام تازه ایجاد نمی‌کند؛ برای ارسال مجدد آگاهانه، از ارسال دستی سفارش استفاده کنید. هر بار بازکردن فرم و ارسال دستی یا آزمایشی یک درخواست جدید است؛ تکرار ارسال همان فرم، درخواست تکراری ایجاد نمی‌کند.

## حریم خصوصی و سرویس بیرونی

افزونه برای ارسال، شمارهٔ گیرنده، متن پیام، قالب اصلی و شناسهٔ فروشگاه و نسخه و متغیرهای استفاده‌شده در صورت پشتیبانی، فرستندهٔ انتخابی و کلید احراز هویت را از طریق HTTPS به پنل آوای تنظیم‌شده ارسال می‌کند. اگر در متن از متغیرهای سفارش استفاده کنید، همان اطلاعات سفارش نیز در متن ارسالی قرار می‌گیرد. برای جزئیات سرویس و سیاست داده‌های آوا به [پنل آوا](https://ava.tarpardaz.com) مراجعه کنید.

بازکردن صفحهٔ تنظیمات یا تازه‌سازی دستی موجودی، درخواست GET با کلید احراز هویت برای دریافت سه مبلغ کیف پول می‌فرستد؛ این درخواست اطلاعات مشتری، سفارش یا متن پیامک ندارد. فقط نتیجهٔ معتبر یا خطای عمومی تا ۶۰ ثانیه در transient وردپرس ذخیره می‌شود و تغییر نشانی یا کلید، cache حساب قبلی را به کار نمی‌گیرد.

گزارش محلی شامل شماره، متن پیام و وضعیت ارسال در پایگاه دادهٔ وردپرس نگهداری می‌شود. شماره‌ها در فهرست گزارش به صورت پوشیده نمایش داده می‌شوند، اما دادهٔ اصلی در پایگاه داده باقی می‌ماند. دورهٔ نگهداری پیش‌فرض ۳۰ روز است و از تنظیمات قابل تغییر است؛ پاک‌سازی فقط رکوردهای دارای نتیجهٔ نهایی را حذف می‌کند و درخواست‌های بلاتکلیف برای پیگیری حفظ می‌شوند. دسترسی به تنظیمات، ارسال دستی و گزارش‌ها به مدیرانی با مجوز `manage_woocommerce` محدود می‌شود. بکاپ پایگاه داده و دسترسی افزونه‌های دیگر نیز باید مطابق سیاست فروشگاه مدیریت شود.

فهرست گزارش‌ها و شمارش آن‌ها حداکثر ۶۰ ثانیه در کش شیء وردپرس ذخیره می‌شوند. تغییر صف، وضعیت پیام یا پاک‌سازی رکوردها، نسخهٔ کش نمایشی را باطل می‌کند؛ تصمیم‌های ارسال و پیگیری همیشه از پایگاه داده خوانده می‌شوند.

## توسعه و ساخت بسته

```sh
php tests/run.php
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 scripts/package.py
```

برای آزمون صف، افزونهٔ PHP `pdo_sqlite` نیز لازم است؛ نصب معمول افزونه به SQLite وابسته نیست. بسته در پوشهٔ `build/` همراه فایل SHA256 ساخته می‌شود. ساخت تکراری از فایل‌های یکسان خروجی یکسان می‌دهد. آزمون‌ها از دادهٔ نمونه و HTTP شبیه‌سازی‌شده استفاده می‌کنند و به مشتری واقعی پیام نمی‌فرستند. گردش CI نحو PHP و آزمون‌ها را روی نسخه‌های PHP 7.4، 8.2 و 8.4 اجرا می‌کند.

### اعتبارسنجی نسخهٔ ۱٫۰٫۰

آزمون یکپارچه در یک نصب محلی و موقت با وردپرس **7.1.4**، ووکامرس **11.2.1**، PHP **8.5.4** و MariaDB **11.8.6** انجام شد. ایجاد سفارش، رویدادهای تسویه‌حساب، اعلان‌های وضعیت، صف و گزارش ارسال، و دسترسی مدیر در هر دو حالت ذخیره‌سازی کلاسیک سفارش و **HPOS** بررسی شدند. ارتباط پیامکی در این آزمون‌ها شبیه‌سازی شد و پیامک واقعی ارسال نشد.

مجموعهٔ مستقل نیز **۱۸۵ بررسی رفتاری PHP** و **۳ آزمون بسته‌بندی** را گذراند؛ از جمله شماره‌های فارسی، قالب‌ها، احراز هویت، جلوگیری از ارسال تکراری، نتیجهٔ نامشخص ارسال، تغییر حساب آوا و الزامات امنیتی فرم‌های مدیریت. این نتیجه مربوط به نسخه‌های نام‌برده است؛ سازگاری با افزونه‌ها و قالب‌های دیگر باید در محیط آزمایشی فروشگاه بررسی شود.

نسخهٔ **۱٫۱٫۰** در PHP **8.5.4** با **۲۸۶ بررسی رفتاری** و **۳ آزمون بسته‌بندی** بررسی شد؛ HTTP کاملاً شبیه‌سازی‌شده بود. قرارداد مالی صحیح IRR، cache و تعویض حساب، خطای شبکه و پاسخ نامعتبر، نمایش فارسی و مجوز/nonce تازه‌سازی پوشش داده شدند. این بررسی مستقل جایگزین آزمون نصب واقعی وردپرس/ووکامرس نیست و پیامک واقعی ارسال نکرد.

نسخهٔ **۱٫۲٫۰** با **۳۲۶ بررسی رفتاری PHP** و **۳ آزمون بسته‌بندی**، بدون ارسال واقعی و با HTTP شبیه‌سازی‌شده بررسی شد. ثبات نسخه در تغییر مشخصات سفارش، ویرایش و بازگرداندن قالب، تصویر ثابت صف، جداسازی فروشگاه کپی‌شده و سازگاری قالب و متن نهایی پوشش داده شدند. شش بردار مصنوعی بین PHP و API برای بررسی قرارداد قالب نیز در `tests/template-context-vectors.php` آماده است.

برای انتشار نسخهٔ جدید، شمارهٔ نسخهٔ افزونه و `readme.txt` را هماهنگ کنید، آزمون‌ها را اجرا کنید و تگ `vX.Y.Z` را ارسال کنید. گردش انتشار، ZIP قابل نصب و checksum را در GitHub Releases قرار می‌دهد. افزونه به‌روزرسان خودکار اختصاصی یا انتشار خودکار در WordPress.org ندارد.

## English

Ava SMS notifications for WooCommerce by Tarahan Shomal. Configure customer status messages, administrator notifications, reusable placeholders, manual order messages and an explicit paid test. The plugin uses Ava's public Bearer-token SMS API, asynchronous processing, idempotency keys, permission checks and HPOS-compatible WooCommerce order APIs. Install the release ZIP, open **WooCommerce → Ava SMS**, enter your panel URL and a key with `sms:send` / `sms:read`, then enable automatic notifications. Persian is the primary interface language. Queued messages are not proof of delivery; uncertain sends are never automatically retried.
